# Kinetic Logic Labs UI and UX Audit

## Scope

Reviewed the live site at 1440 × 900 (desktop), 768 × 1024 (tablet), and 390 × 844 (mobile). Pages reviewed: Home, About, Projects, Repository, and Contact. This is an audit only; no production UI code was changed.

Severity scale: **Critical** blocks a primary user task or makes a major navigation destination appear broken. **High** materially undermines credibility, readability, or responsive usability. **Medium** weakens hierarchy or polish. **Low** is a refinement after the larger problems are resolved.

## Findings

| ID | Page and component | Issue and why it feels generic or unprofessional | Severity | Specific recommended change |
| --- | --- | --- | --- | --- |
| 01 | Projects — `App` projects route | The Projects navigation destination renders no content at any tested width: only the global grid, header, and footer remain. A portfolio’s primary proof-of-work page therefore looks unfinished rather than intentionally minimal. | Critical | Implement a project index before promoting this route: show 3–6 real project records with a title, one-sentence research question, role, methods/tools, outcome, date, and a link to evidence such as a case study, repository, CAD file, or competition result. Until then, remove the top-level navigation item or label it clearly as “Selected work — coming soon.” |
| 02 | Repository — `App` repository route | Repository is also entirely blank at desktop, tablet, and mobile. It promises an archive but supplies no technical artifacts, creating an immediate trust gap for an engineering/research portfolio. | Critical | Add a concise repository catalog with links to real GitHub repositories, notebooks, CAD exports, reports, or datasets. Each item should state the artifact type, purpose, tools, last update, and access level. If materials are private, say so and provide a request path rather than an empty route. |
| 03 | Global — `Header` tablet breakpoint | At 768 px, the desktop navigation remains visible while the mobile menu has not yet appeared. The brand is clipped to “ABS” and the header has no safe spacing budget. This is a conspicuous responsive failure at a common tablet width. | High | Move the header breakpoint earlier (for example, switch to the compact/mobile navigation before the combined brand, five links, divider, and search control no longer fit), or use a dedicated tablet layout with a shorter wordmark and fewer visible navigation controls. Test at 768 px, 820 px, and 1024 px. |
| 04 | Global — `BackgroundGrid`, `index.css`, and content layers | The high-opacity grid sits over headings, body copy, images, inputs, and the footer. On About and Contact it substantially reduces apparent contrast and makes the interface look like a decorative “tech template” rather than a deliberate research presentation. | High | Reduce the grid contrast sharply, constrain it to selected sections, or place it behind opaque/near-opaque reading surfaces. Establish a foreground/background contrast target of at least WCAG AA for ordinary text; verify actual rendered colors rather than relying on Tailwind opacity tokens. |
| 05 | Home — `ScrollVideoScrubber` | The hero is a collage of stock interiors, generic code screens, and abstract art. It reads as a fashionable agency moodboard, not evidence of engineering or research work. On one desktop load, the hero briefly rendered as an empty grid before the imagery appeared, making the experience feel unstable. | High | Replace the stock collage with project-authored material: CAD models, annotated prototypes, lab notebooks, experiment photos, computational visualizations, or a single strong project image. Provide a defined poster/fallback state so the hero has meaningful content before media or animation is ready. |
| 06 | Home — `ScrollVideoScrubber` | “Welcome” and “Scroll to Explore” do not communicate what Kinetic Logic Labs does, for whom, or why its work matters. The dominant hierarchy is visual spectacle, while the value proposition is absent. | High | Use a specific research-led headline and a short supporting statement, e.g. identify the focus area, kinds of artifacts, and current work. Add one primary action that leads to selected work or a featured case study; keep “About” as a secondary path. |
| 07 | About — `OurTeam` | The page title says “About me,” while the Home call-to-action says “Meet the Core Research Faculty” and the brand says “Labs.” This switches between a personal student profile, a research group, and an educational institution without explaining the relationship. The mismatch feels fabricated because the institutional language exceeds the evidence presented. | High | Decide on the site’s identity and use it consistently. For an individual portfolio, use “About Ziyao Xu,” “Selected work,” and “Research interests.” For a lab, identify team members, advisors, affiliations, projects, and a clear institutional context. Remove “faculty” unless it is factually accurate. |
| 08 | About — `OurTeam` desktop scrollytelling | The inactive narrative blocks are intentionally rendered at very low opacity. In the reviewed desktop state, the key biographical text was difficult to read against the grid, and the experience requires scroll-based discovery for basic information. This prioritizes animation over accessible reading. | High | Keep all essential text at readable contrast and normal opacity. Use the sticky media treatment only as progressive enhancement; present each achievement as a conventional, independently readable section with a heading, concise summary, evidence, and image caption. |
| 09 | About — `OurTeam` content and media | The biography is extremely general (“I enjoy many activities in STEM”), while the visual emphasis is a portrait and a carousel. The strongest claims—National Science Olympiad results and CAD work—lack dates, event links, artifacts, or explanatory context. This feels more like a generic personal landing page than a research portfolio. | High | Reframe the page around evidence: research interests, methods, selected achievements, and concrete outputs. Add competition/event dates, a short project description, supporting documentation or external links, and captions explaining what each image or CAD artifact demonstrates. |
| 10 | Contact — `App` contact route and `InquiryForm` | The form surface, placeholder text, labels, and body copy are all very low contrast on the dark grid. In particular, form fields are difficult to distinguish from the background, which harms scanning and accessibility. | High | Put the form on an opaque surface and use a tested type scale and color pair for labels, entered text, placeholders, borders, and focus states. Avoid relying on faint borders as the only field boundary. Validate keyboard focus and contrast for each state. |
| 11 | Contact — `InquiryForm` | “Send response” is unnatural product language for a visitor initiating a message. The form opens the user’s mail client but then presents a delayed “Email Prepared” state, which can imply that a submission occurred. This reduces clarity and feels like a template interaction pasted onto a static site. | Medium | Rename the action to “Open email draft” or replace it with a real form submission flow. If retaining `mailto:`, explain the behavior immediately adjacent to the button and do not show a success state until an actual delivery service confirms receipt. |
| 12 | Global — `Header`, `Footer`, `index.css` | The visual system layers a frosted header, grid background, heavy shadows, rounded cards, animated transitions, a scramble effect, and repeated thin borders. Individually these are common UI motifs; together they create an over-styled, template-like “futuristic dashboard” aesthetic that competes with the portfolio content. | Medium | Reduce the system to a smaller set of purposeful motifs: one restrained grid or measurement detail, one surface treatment, a consistent radius scale, and limited motion reserved for content transitions that clarify state. Remove decorative effects that do not communicate technical information. |
| 13 | Global — `Header` and `Footer` (also present in unused `GalleryArchive` and `ProgramCard`) | The all-caps mono navigation and footer copy are paired with pseudo-technical phrases in the available portfolio components (for example, “STUDENT_geometry_DOCKET_2026,” “CORE_TOPOLOGICAL_FOCUS,” and “COMPILED_OUTPUT”). This language reads as generated sci-fi interface copy when it is not tied to real artifacts. The rendered footer also contains the grammatical error “a engineering and design firm.” | Medium | Use plain, domain-accurate labels: “Selected projects,” “Methods,” “Files,” “Coursework,” or “Project metadata.” Reserve mono type for data values and technical annotations with real meaning. Rewrite the footer as a concise, factual description and correct the grammar. |
| 14 | Home and global navigation — `App`, `Header`, `Footer` | The Home page has very little content after the hero, while the footer repeats the same five links. The primary user journey is therefore a decorative landing frame followed by blank destinations, not a coherent research narrative. | Medium | Establish a clear information hierarchy: Home should introduce the portfolio, feature 2–3 real projects, state areas of inquiry, and link to deeper pages. The footer should support—not substitute for—the primary information architecture. |
| 15 | Mobile — `Header` and `ScrollVideoScrubber` | The compact header works at 390 px, and the mobile menu is legible, but the hero consumes most of the initial viewport with large decorative imagery and no substantive context. The first useful explanatory information is deferred behind scrolling and navigation. | Medium | Keep the mobile hero shorter and lead with the portfolio’s subject matter. Use one project-relevant visual, a concise proposition, and a visible next step within the first screen. Preserve the menu treatment, but keep its menu labels and spacing aligned with the desktop information architecture. |
| 16 | Mobile — About and Contact components | The content stacks without horizontal overflow, but the reading surfaces remain too dark and the form becomes a long, visually undifferentiated sequence. The About portrait dominates the first screen more than the biography or evidence of work. | Medium | On small screens, increase text/background separation, shorten vertical gaps around the form, and lead About with a one-sentence focus plus evidence links before the portrait. Ensure inputs, labels, and actions have a clear visual grouping. |
| 17 | Global — accessibility semantics in `Header` and logo controls | The visual wordmark in the header and footer is clickable but is implemented as a generic `div`, not a keyboard-operable control. Decorative images also carry repeated generic alternative text on Home rather than communicating a project. | Medium | Use a real link or button for the home/brand action with an accessible name. Make decorative imagery `alt=""`; give substantive project imagery concise, descriptive alt text and captions. |
| 18 | Global — motion in `ScrollVideoScrubber`, `OurTeam`, and `Header` | Scroll interception, frequent animation, text scrambling, and auto-playing media can feel performative rather than informative. They also increase cognitive load and can be uncomfortable for motion-sensitive users. | Medium | Honor `prefers-reduced-motion`, eliminate scroll hijacking for ordinary reading, stop auto-advancing nonessential carousels, and use animation only to reveal state changes or data relationships. |
| 19 | Shared design language — `index.css`, `Header`, `InquiryForm`, cards | Radius, shadow, and surface treatments are not coherent: the hero images use several rounded shapes and heavy shadows; cards alternate between `rounded-lg`, `rounded-xl`, and `rounded-2xl`; the header is frosted while main content is intentionally dark and nearly flat. The result lacks the disciplined precision expected of an engineering portfolio. | Low | Define a compact token set and enforce it: for example, one small radius for controls, one medium radius for images/cards, one elevation style, and one or two border weights. Use those tokens to differentiate content hierarchy instead of decorative variety. |

## Recommended order of work

1. Resolve the two blank primary routes and clarify whether this is an individual portfolio or a lab/educational organization.
2. Repair tablet navigation and all major contrast/readability failures.
3. Replace the stock-collage hero and generic copy with real projects, artifacts, and research context.
4. Simplify the visual language and motion after the content hierarchy is in place.
5. Run a focused accessibility pass covering keyboard navigation, focus states, contrast, reduced motion, and form behavior.
